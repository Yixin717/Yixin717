## 最近在做的：Content Guard / 文案安检

小红书带货文案的「发布前合规体检」。

我自己就是第一个用户：平台只回一句“涉嫌违规”，不说哪句、违反哪条；商家只能凭感觉改一版、再发一版。  
所以我想做一件事：发之前，先把可能出事的句子找出来，告诉商家违反了哪条规则，再给一版能直接用的改写。

它不是“AI 文案生成器”。生成只是次入口；主功能是检查和修订。

现在它大概能做这些：

- 按 40 条规则逐句检查，每条规则都能指回法条或平台原文；
- 每条违规指回原句，并给出条款依据；
- 一条违规对应一条改写，编号一一对应，改不了的会标“未自动改写”；
- 模型没把握的，不硬判，转人工确认。

目前它还没有达到能够直接to B的程度，因为无论是前端后端精细度还是规则库的充分程度，都还非常有待提升。但我目前想法是让它“每条结论都能被核对”，让它整个流程不会出问题。

### 怎么验证它有没有用

我找了 24 条真实的小红书带货笔记，自己逐条确认了 8 处违规。  
第一版只找对了 2 处；我改了一版提示词，规则和样本都没动，现在能找对 6 处。报出的问题里，误报从 5/7 降到 4/10；18 条引用全部能对上原文。

这个数字不大，24 条、8 处违规，只能说明方向，不能当“平台准确率”。  
下一步我想补 10–15 条没见过的笔记，看看它换一批题还准不准；也想把“模型没把握”的那部分展示出来，而不是藏起来。

## 我怎么做产品

**先想清楚“什么算对”，再动手。**  
Content Guard 的第一版，我先定义了什么算“命中”：规则要对、原句要逐字对上、模型没把握的要单独放。没有这个标准，改 prompt 就只是碰运气。

**把 AI 当执行者，不是决策者。**  
代码、测试、文档可以交给 AI；但产品边界、什么算违规、什么该放弃，得我自己判断。比如原型里为了演示效果，故意埋了一句“全网最低”，我否掉了——用户是信任你懂条款才来的，不能给他挖坑。

**工程是支撑，不是卖点。**  
能上线、能对账、能迭代，比“用了多少框架”重要。Content Guard 现在能跑起来：有测试、有 CI、有限流、有每日备份；这些不是用来炫耀的，是为了让我敢把它放到线上。
